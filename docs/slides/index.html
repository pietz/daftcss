Daft Slides.

Semantic HTML for presentation decks.

A deck is a stylesheet away.

Add class="deck" to <body>. Each <section> becomes a 16:9 slide. No runtime, no build step, no framework.

Why this exists.

Agents write HTML fluently. They write PowerPoint poorly. Give the agent a vocabulary it already speaks, and the deck writes itself.

  • HTML is the agent's first language
  • Semantic elements carry intent
  • Daft fills in the design

The whole API.

<body class="deck">
  <section class="title">
    <h1>Q4 review</h1>
  </section>
  <section>
    <h2>What shipped</h2>
    <ul><li>…</li></ul>
  </section>
</body>

Two columns, no wrappers.

Drop a .grid inside a slide and its children become equal columns.

Pair a thought with a picture, a claim with evidence, a before with an after.

Weighted layouts with .span-2.

One child claims two tracks, the other claims one. You get a 2:1 split with the same vocabulary you use everywhere else in Daft.

No new primitives. Same .grid, same .span-N.

Three things this gives you.

Semantic

A <section> is a slide. A <blockquote> is a pull quote. Markup carries meaning.

Themable

Slides inherit Daft tokens. Change --primary at the root and the whole deck retunes.

Portable

One HTML file. Email it, host it, version it in git, diff it in a pull request.
